# Clerk Authentication — Implementation Plan

## Background

Fresh Next.js 16.2.1 project with Tailwind CSS v4, TypeScript, and App Router. No existing auth, no additional packages beyond the defaults. Goal: integrate Clerk for full authentication including login, registration, OTP, password reset, RBAC, session management, and optional 2FA.

---

## User Review Required

> [!IMPORTANT]
> **Clerk API Keys** — You must create a Clerk application at [clerk.com](https://clerk.com) and provide:
> - `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`
> - `CLERK_SECRET_KEY`
>
> Without these the app will not start.

> [!IMPORTANT]
> **Role Assignment** — Roles (`admin` / `client`) will be stored in Clerk's `publicMetadata`. You'll need to assign roles either:
> 1. Manually via Clerk Dashboard → Users → Edit metadata, OR
> 2. Via a Clerk webhook + API route (can be added later)
>
> Which approach do you want for MVP?

> [!WARNING]
> **Font Choice** — The default project ships with Geist / Geist Mono (system-ish fonts). Per your design rules, these are disallowed. I'll replace them with **Sora** (headings) + **DM Sans** (body) — a distinctive pairing that matches a financial/accounting aesthetic. Let me know if you prefer something else.

### 4 · Middleware (Route Protection + RBAC)

#### [NEW] `middleware.ts` (project root)

```
clerkMiddleware with:
  - Public routes: /sign-in(.*), /sign-up(.*), /
  - Protected routes: /dashboard(.*)
  - Admin routes: /admin(.*)  → redirects non-admin users
```

Uses `createRouteMatcher` and `auth.protect()` from the latest Clerk API.

---

### 5 · TypeScript Declarations

#### [NEW] `types/globals.d.ts`

Extend `CustomJwtSessionClaims` to type `metadata.role` for compile-time safety:

```ts
export {}
declare global {
  interface CustomJwtSessionClaims {
    metadata: { role?: "admin" | "client" }
  }
}
```
